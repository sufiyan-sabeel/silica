# The parity contract

Executable form of §16.3 of `docs/design/SILICA_PLATFORM_ARCHITECTURE.md`: the
observable behaviour a second implementation of the VM must reproduce exactly.

`tests/test_parity_contract.py` runs every case here through the reference VM and
compares byte for byte.

| File | Meaning |
|---|---|
| `<name>.sc` | the program |
| `<name>.expected` | exact stdout, when the program succeeds |
| `<name>.stderr` | exact diagnostic, hints included, when the program is supposed to fail |
| `<name>.exit` | optional exit-code override; otherwise 0 for success cases, 1 for error cases |

Rules:

* expectations are generated by running the reference VM — never hand-written;
* a case whose first line starts `# xfail(strict):` records a **known defect
  in the Python VM**; the expectation holds the *correct* behaviour, so the case fails
  today and the test passes by design, and it fails loudly once the defect is
  fixed so the marker gets removed;
* the cases are deliberately small. They are a contract, not a test suite: the
  behaviour they pin is the behaviour two VMs are most likely to disagree about.
